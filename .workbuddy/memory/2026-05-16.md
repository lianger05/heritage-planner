# 2026-05-16 工作日志

## 古建文旅经济智能规划助手项目 - 初始化构建

### 项目决策
- 选择方向三：古建文旅经济智能规划助手
- 用户定位：文旅规划从业者、地方文旅局、学术研究者
- 核心价值：AI自动生成"保护性开发方案"初稿，平衡文物保护红线与经济效益

### 已完成
1. **项目骨架搭建**: Monorepo结构 (backend/frontend/data/docs)
2. **后端 FastAPI 骨架**:
   - 核心配置 (config.py, database.py)
   - ORM模型 (Heritage, Plan, ChatSession, Regulation)
   - Pydantic Schema (完整API数据契约)
   - AI引擎层 (LLM服务、RAG检索、知识图谱、规划生成)
   - API端点 (heritage/plan/chat/regulation/report/map)
3. **前端 Next.js 骨架**:
   - 页面路由 (首页/地图/规划/报告/项目)
   - API客户端 (api.ts)
   - 状态管理 (Zustand store)
   - TypeScript类型定义
4. **数据层**:
   - 数据库建表SQL (PostGIS)
   - 开封古建种子数据 (10处)
   - 法规种子数据 (5条)
   - RAG向量入库脚本
5. **Docker部署**:
   - docker-compose.yml (PostgreSQL/Neo4j/Redis/ChromaDB/MinIO/Backend)
   - Dockerfile (backend + frontend)
6. **项目文档**:
   - README.md
   - ARCHITECTURE.md (架构设计 + 其他AI填充指南)

### 技术栈确定
- 前端: Next.js 14 + TypeScript + Tailwind + shadcn/ui
- 后端: FastAPI + SQLAlchemy + Pydantic
- AI: DeepSeek/Qwen + LangChain + ChromaDB + Neo4j
- 数据: PostgreSQL/PostGIS + Redis + MinIO

### 关键设计
- 方案生成流程: 知识图谱→RAG法规→RAG案例→LLM生成→约束校验
- LLM Prompt: 规划专家角色 + 严格JSON输出 + 法规注入
- 多轮对话: 会话ID + 方案上下文注入 + 最近20条消息
- 数据起步: 河南开封（10处古建种子数据）
