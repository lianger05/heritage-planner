# 2026-05-17 工作日志

## 古建文旅经济智能规划助手项目 - 本地启动

### 核心变更：适配无Docker本地开发环境

原项目设计依赖 Docker（PostgreSQL/Neo4j/Redis/ChromaDB/MinIO），但用户机器无 Docker。
进行了全面降级适配：

1. **数据库**: PostgreSQL + PostGIS → SQLite + aiosqlite
   - `database.py`: 改用 `sqlite+aiosqlite` 引擎
   - `heritage.py` ORM: 去掉 GeoAlchemy2 Geometry 字段，改用 Float 存经纬度
   - 新增 `init_db()` 自动建表
   - 新增 `_seed_data()` 自动加载种子数据（10古建+5法规）

2. **LLM服务**: Redis缓存 → 本地内存字典缓存
   - `llm_service.py`: 去掉 Redis 依赖，用 `_local_cache` 字典
   - 增加 `is_available` 属性检测API Key是否配置
   - 无API Key时优雅降级，返回提示信息

3. **RAG服务**: ChromaDB HTTP → 本地 PersistentClient
   - `rag_service.py`: 延迟初始化 ChromaDB，持久化到 `./data/chroma_db/`
   - 无 ChromaDB 时搜索返回空列表而非报错

4. **知识图谱**: Neo4j → 本地内存种子数据
   - `kg_service.py`: 新增内存模式，内置5个开封古建+8个朝代+5种风格+4个保护等级
   - 相似古建按"同朝代+同风格+同保护等级+同建筑类型"计算
   - 保留 Neo4j 代码路径，配置 `neo4j_enabled=True` 时自动切换

5. **地图端点**: PostGIS空间查询 → 纯Python过滤
   - `map.py`: 去掉 `ST_X/ST_Y/ST_Within/ST_MakeEnvelope` 依赖
   - 用 Python 直接比较经纬度范围

6. **ORM模型修复**: `mapped_column(back_populates=...)` → `relationship(back_populates=...)`
   - SQLAlchemy 2.0 关系字段必须用 `relationship()` 而非 `mapped_column()`
